Big ideas

  • Transformers enable parallel computation over training inputs with self-attention; autoregressive generation still produces tokens sequentially.
  • Self-attention uses Query, Key and Value vectors: compare a word's Query with every Key, softmax the scores into weights, and sum the weighted Values.
  • A plain LLM uses supplied context; RAG adds retrieved information; an agent selects steps or tools and can also use RAG.
  • An agent sits at the centre, using one or more LLMs plus integrations (tools, vector store, prompt recipes); frameworks like LangChain or LlamaIndex help build it.
  • Generative model families: encoder models (VAE), GANs, autoregressive, flow, energy-based and diffusion models.
  • Foundation models are pre-trained once on massive data (high cost, high performance) and then adapted by fine-tuning or prompt engineering.
  • GenAI tech stack: hardware, cloud platforms, foundation models, customisation, then end-to-end applications.
  • Business value: creativity, personalisation, faster answers, simplifying complex systems, automating admin, content at scale.

From RNNs to Transformers

The short history that led to Transformers, contrasting the sequential RNN with the parallel, attention-based Transformer.

Transformers: parallelism and context

Transformers improve training parallelism and context handling.

  • RNNs → propagate state step by step
  • Self-attention → connects positions directly; allows parallel computation over known training inputs
  • Autoregressive Transformer → still generates its output token by token

Parallel training does not mean all future output tokens are known at once.

Contrast the information path

  • RNN → passes context through recurrent state
  • Self-attention → a position combines allowed context positions directly
  • Helps → large-scale training and long-range relationships
  • No guarantee of perfect understanding

Origins and names

  • 2017 paper → Attention Is All You Need introduced the Transformer
  • GPT = Generative Pretrained Transformer
  • GPT, Claude, Gemini → examples of model families
  • Not a claim that one vendor's model descended from another vendor's product
RNN
Recurrent Neural Network: processes a sequence one step at a time, carrying state forward.
Transformer
Neural network architecture (2017) that processes sequences in parallel using self-attention.
GPT
Generative Pretrained Transformer, the model family behind ChatGPT.

Check yourself

A team training a language model on a large corpus finds an RNN takes weeks because each step waits for the previous one. Why would a Transformer train faster on the same hardware?
  • RNN: passes context through recurrent state one step at a time → training can't be parallelised across a sequence
  • Self-attention: connects positions directly → computation over the known training input can run in parallel, which suits GPU hardware
  • Long-range links: also links distant words without passing through every step in between
A colleague says 'Transformers process everything in parallel, so a chatbot built on one generates its whole answer at once'. Is that right?

No. Parallelism applies to training over known inputs.

  • Autoregressive Transformer (such as a GPT-style model) still generates output token by token
  • Each new token predicted from the context so far
  • → response time grows with answer length
  • → streaming the output token by token is common in chat applications

How self-attention works

Self-attention explained with a library analogy (Query, Key, Value) and a four-step computation giving each word a context-rich representation.

Self-attention: Query, Key, Value

Each word builds its meaning from the words that matter most to it. Analogy:

  • Query → your question about the current word
  • Keys → the labels of every other word you match against
  • Values → the content you collect from the best matches

Four steps per token

  1. Form learned Query, Key and Value vectors
  2. Score the Query against allowed Keys
  3. Softmax → obtain weights summing to 1
  4. Sum the weighted Values

Lecture illustration: 'it' attends more to 'animal' than 'street'. The numbers are explanatory examples, not fixed learned rules.

Result and attention types

  • Result → a context-rich representation
  • Encoder self-attention → can use a whole input
  • Causal decoder attention → masks future positions
  • Encoder-decoder models → also use cross-attention to connect decoder queries with encoder outputs
Self-attention
Mechanism combining Value vectors using Query–Key relevance weights over allowed context positions.
Query / Key / Value
Three learned vectors per word: the question, the label to match against, and the content to take.
Softmax
Function that turns raw scores into weights that add up to 1.

Check yourself

In 'The animal didn't cross the street because it was tired', explain how self-attention gives 'it' the right meaning, and what would change in 'because it was too wide'.
  • Query for 'it' is scored against every word's Key
  • Softmax turns the scores into weights
  • Weighted sum of Values → 'it' gets a representation built mostly from 'animal'
  • 'because it was too wide': the context changes the scores → 'street' would get the higher weight

The weights are learned from data, not fixed rules.

What would go wrong if the attention scores were used directly as weights, without softmax?
  • Raw scores: on an arbitrary scale and can be negative
  • → the weighted sum of Values would not be a proper average; could be dominated by scale rather than relevance
  • Softmax: turns the scores into positive weights that sum to 1 → output is a weighted average that favours the best-matching words
A text-generation model must not use words that come later in the sentence when predicting the next word, but a translation model's encoder can read the whole source sentence. How does attention differ between them?
  • Generating decoder: causal attention → masks future positions, so each token attends only to earlier ones
  • Encoder: self-attention can use the whole input
  • Encoder-decoder models: also cross-attention → the decoder's queries can look at the encoder's outputs

LLM vs RAG vs Agents, and what GenAI is

Three ways of using a language model (plain LLM, RAG, agent), the parts of an autonomous agent, and a definition of Generative AI.

LLM vs RAG vs agent

Choose by missing information or action.

  • Plain LLM → learned parameters plus the supplied prompt/context; does not inherently fetch current company data
  • RAG → retrieves documents and adds them to that context
  • Agent → can select tools and act over several steps, often also using retrieval

These patterns combine; they are not a compulsory ladder.

Agent architecture

  • Core → interface, model, instructions, integrations
  • Lecture adds → planning, tool access, memory/context
  • Vector store → one retrieval option
  • Orchestration frameworks → connect these pieces
  • Persistent vector memory is not required for every tool-using agent

Generative AI vs agentic AI

  • Generative AI → the part of machine learning that learns the patterns and distribution of a training dataset and samples new, similar content from it
  • Example → new owl images from random noise
  • Agentic AI goes further:
    • sets goals
    • plans
    • acts autonomously
    • adapts
RAG
Retrieval-Augmented Generation: fetch relevant context and give it to the LLM with the prompt.
AI agent
An LLM-centred system that selects steps or tools to pursue a task; it can use retrieval and memory where needed.
Vector store
Database of embeddings used to find semantically similar content for context and memory.
LangChain / LlamaIndex
Orchestration frameworks for wiring LLMs to data, memory and tools.

Check yourself

An HR chatbot built on a plain LLM call gives confident but outdated answers about this year's leave policy. Which pattern fixes this, and why not retrain the model?

RAG, not retraining.

  • RAG: retrieve the current policy documents and add them to the prompt → answers grounded in the company's own, up-to-date data
  • Plain LLM: only knows its training data plus the prompt
  • Retraining: costly and goes stale again with the next policy change; updating the document index is cheap

Keep the index current, because RAG is only as fresh as its sources.

A RAG assistant retrieves the refund policy correctly. The business now wants it to issue refunds as well. What changes in the design, and what new risk appears?

It becomes an agent.

  • Tool selection: the model selects tools, such as calling the order and payment service APIs
  • Multi-step: acts over several steps, still using retrieval for policy
  • New risk: retrieval gave the model information, not permission
  • Safeguards: each tool needs authorisation checks, limits such as a refund cap, and logging, with human approval for high-value actions
A team building an agent that calls two internal APIs says it must first set up a vector store for memory. Is that required?

No. A vector store is one retrieval option.

  • Lecture's agent architecture: an interface, a model, instructions or a prompt recipe, planning, tool integrations, memory or context
  • Tool-using agent with short tasks: may need only conversation context
  • Add a vector store when the agent must retrieve from a large document set
A RAG assistant cites a company document but still gives a wrong answer. Give two likely causes and how you would confirm each.
  1. Stale or irrelevant passage retrieved → confirm: check the retrieved chunks and their dates
  2. Model misread correct context → confirm: check whether the answer is actually supported by the retrieved text

Retrieval is not a correctness guarantee, so evaluate retrieval quality and answer support separately.

Model families, value and the GenAI stack

Six families of generative models, why businesses want GenAI services, and foundation models with the layered GenAI tech stack.

Six families of generative model

Each generates differently.

  • Variational autoencoders (VAEs) → compress and decode data
  • GANs → pit a generator against a discriminator
  • Autoregressive models → predict the next value from previous ones (how LLMs write text)
  • Flow models → transform simple distributions into complex ones
  • Energy-based models → low energy to real data, high to others
  • Diffusion models → learn to reverse a defined noise-adding process

GAN vs diffusion: adversarial competition vs reversing gradual noising.

Why businesses want GenAI services

  • Creativity
  • Smart suggestions
  • Personalisation
  • Instant answers
  • Simplifying complex systems with plain language
  • Automating admin work
  • Content at scale

Foundation models

  • Pre-trained once, at high cost, on massive broad data
  • Then adapted → fine-tuning, prompt engineering
  • To many tasks:
    • Q&A
    • extraction
    • captioning
    • instruction following

GenAI tech stack, bottom up

  1. Hardware → GPUs/TPUs
  2. Cloud platforms → scalable compute, storage, AI services
  3. Foundation models → closed via API, or open-weight with released parameters
  4. Customisation
  5. End-to-end applications

Closed vs open models

  • Closed → ready to use but ties you to a provider
  • Released weights → can allow self-hosting and tuning under their licence
  • Open cost → operating the model
GAN
Generative Adversarial Network: a generator and discriminator trained against each other.
Diffusion model
Learns to reverse a noise-adding process, generating data by gradually denoising.
Foundation model
Large model pre-trained on massive broad data, adapted to many downstream tasks.
Model hub
Platform to share and host models, e.g. Hugging Face.
Fine-tuning
Further training a pre-trained model on domain data to specialise it.

Check yourself

A design team wants a model that generates realistic product images, and is comparing a GAN with a diffusion model. Explain how each generates, as the basis for the comparison.
  • GAN
    • Trains a generator against a discriminator that tries to tell real images from generated ones
    • Generates in one pass from the trained generator
  • Diffusion model
    • Learns to reverse a defined noise-adding process
    • Generates by progressively denoising a random sample over many steps

The comparison: adversarial training vs iterative denoising.

A hospital must keep patient text inside its own environment, but wants to summarise clinical notes with a language model. Closed model through an API, or open-weight model self-hosted?

Open-weight model, self-hosted in the hospital's environment.

  • Fits the data constraint: the released weights allow deployment and tuning under their licence without sending notes to a provider
  • Cost: operating GPUs, capacity, updates and reliability
  • Closed API: ready to use but ties you to the provider and sends data outside

A closed API fits only if its terms and deployment options meet the constraint.

A startup plans to train its own foundation model for customer-support answers. What does the GenAI stack suggest instead?

Most teams add value higher up the stack.

  • Foundation models: expensive to pre-train but reusable across many tasks
  • Customisation: prompt engineering, RAG or fine-tuning
  • End-to-end application

Training their own model is justified only for a capability or a data constraint that existing models can't meet.

Exam-style questions

Answer aloud or on paper before opening.

Design a GenAI customer-support assistant for a cloud-native e-commerce platform that must answer from current product and policy documents and also check order status. Choose plain LLM, RAG or agent, and say how it fits into the existing microservices.

RAG for answers, extended to an agent for order status.

  • RAG: retrieve current product docs, FAQs and policies from an index such as a vector store → responses grounded without retraining
  • Agent tools: order status by calling the order service's existing API with the customer's own authorisation
  • Refunds stay behind human approval
  • Fit with microservices: run the assistant as its own service behind the API gateway, using a hosted foundation model through an API or a self-hosted open-weight model
  • Monitor retrieval quality and answer support

Retrieval doesn't guarantee correctness.

Explain the layers of the GenAI tech stack, and advise a 10-person cloud-native team on where to invest and where to buy.
  • Layers, bottom up
    • Hardware: GPUs/TPUs
    • Cloud platforms: scalable compute, storage, AI services
    • Foundation models: closed through an API, or open-weight
    • Customisation: prompt engineering, RAG, fine-tuning
    • End-to-end applications
  • Buy the bottom three
    • Pre-training is high-cost
    • Existing models are reusable
  • Invest in customisation and the application
    • Where the team's data and domain knowledge create value

Choose closed versus open weights by data constraints and operating capacity.

An enterprise wants GenAI for expense processing: answer staff questions about the policy, read receipt images and submit claims. Compare a plain LLM, RAG and an agent for this, and design the safeguards for the part that acts.
  • Plain LLM: can interpret text but doesn't know the company's current policy
  • RAG: adds the retrieved policy → enough for staff questions
  • Agent with tools calling the expense system's API: needed for extracting receipt data and submitting claims
  • Safeguards for the part that acts
    • Tools act only with the employee's permissions
    • Limits route claims above a threshold to human approval
    • Every action is logged
    • Agent can only prepare or submit within defined integrations

The patterns combine, but an answer is not a permitted business action.

A product manager asks why chat responses get slower as answers get longer, even though 'Transformers are parallel'. Explain using the RNN-to-Transformer change, and give one design implication for a cloud-native chat service.
  • RNN → Transformer: step-by-step recurrence replaced by self-attention
  • Training: runs in parallel over known inputs and links distant context directly → made large-scale training possible
  • Generation: still autoregressive; each token predicted from the tokens so far → a longer answer takes longer to generate
  • Design implication: stream tokens to the client as they are generated; set timeouts and capacity by expected output length
A global marketing organisation proposes three GenAI features: personalised video per customer segment, first-draft product copy in 8 languages, and AI-generated ad music. Assess each for business value and risk, and say what process control is needed across all three.
  • Personalised video
    • Value: increases engagement at scale
    • Risk: costliest to generate; most likeness and brand risk
  • Multilingual draft copy
    • Value: clearest time saving
    • Main risk: translation errors
  • Ad music
    • Value: cheap content at scale
    • Risk: its usage terms must permit commercial use
  • Common business value: content at scale, personalisation, faster delivery

Process control across all three: human review and approval before publication, and track the usage terms of each generated asset.
